# Desktop-Pet Landscape Survey

**Purpose.** Factual, sourced survey of every significant desktop-pet (桌宠 / デスクトップマスコット) ecosystem, focused on one question: *what would a host runtime need in order to import and run this ecosystem's pets?*

**Method.** Web research (search + primary-source fetches: GitHub READMEs, official docs, spec pages, license files). Every non-obvious claim carries a source link. Claims that could not be verified are marked **unverified** rather than guessed. Research date: 2026-10-14.

**Reading order.** §1 ecosystem-by-ecosystem tables → §2 ranked support order → §3 common-denominator internal model → §4 blocked / impractical list → §5 prior art on universal pet hosts.

---

## 1. Ecosystem survey

Each entry: canonical URL + license · runtime dependency · on-disk asset format · adapter difficulty (trivial / moderate / hard / legally blocked) · popularity signal · whether the license permits third-party re-hosting of user-created content packs.

### 1.1 Shimeji family (Java)

| Field | Detail |
|---|---|
| **Original** | Yuki Yamada / Group Finity — `group-finity.com/Shimeji` (site dead, archived). Java. Original license **zlib/libpng** |
| **Canonical maintained fork** | **Shimeji-ee** by Kilkakon — <https://kilkakon.com/shimeji/> · **New BSD** for the Shimeji-ee source, **zlib/libpng** for original Shimeji. Latest **1.0.22 (2025-08-16)**. Kilkakon notes the original group "said to use the BSD License, but then didn't even provide any terms", so the page's terms are his own reconstruction |
| **Other forks** | [`DalekCraft2/Shimeji-Desktop`](https://github.com/DalekCraft2/Shimeji-Desktop) (JRE 6 → **JDK 25** port, requires **Java 25+**, Maven, 860 commits, **52★/15 forks**, Win/macOS/Linux(X11); Linux code from `asdfman/linux-shimeji`, macOS from `nonowarn/shimeji4mac`; GitHub reports `NOASSERTION` but the README states New BSD + zlib); [`gil/shimeji-ee`](https://github.com/gil/shimeji-ee) (macOS, based on Kilkakon v1.0.13, **60★/18 forks**, 10 commits); [`estenv/linux-shimeji`](https://github.com/estenv/linux-shimeji) (**zlib**, **165★/24 forks**, **archived**); `LavenderSnek/ShimejiEE-cross-platform` (Java 17 baseline, publishes `mac-jre` and `no-jre` artifacts); `Valkryst/VShimeji` |
| **Runtime** | **Java** (JVM). Original targeted JRE 6; modern forks target JDK 17–25. This is the whole packaging problem: bundle a JRE or require one |
| **Asset layout** | App root: `conf/`, `img/`, `lib/`, `Shimeji-ee.jar`, `Shimeji-ee.exe`/`.sh`. Config: `conf/actions.xml`, `conf/behaviors.xml`, `conf/settings.properties`, `conf/logging.properties`. Per-character overrides at `img/<NAME>/conf/` **or** `conf/<NAME>/`; otherwise the global files apply. Image set `img/<NAME>/` must contain **`shime1.png`–`shime46.png`** (per-frame PNG, one file per pose, no spritesheet); tray icon **`img/icon.png`**; **`img/unused/` is ignored**. Distribution convention: a "shimeji pack" is a ZIP of `conf/` + `img/<Name>/` that users merge into the app folder |
| **Animation format** | XML, root `<Mascot xmlns="http://www.group-finity.com/Mascot" … xsi:schemaLocation="http://www.group-finity.com/Mascot Mascot.xsd">`. `<ActionList>` of `<Action Name= Type= BorderType=>`; `Type` ∈ `Stay`, `Move`, `Animate`, `Sequence`, `Select`, **`Embedded`**; `BorderType` ∈ `Floor`, `Wall`, `Ceiling`. Frames: `<Pose Image="/shime1.png" ImageAnchor="64,128" Velocity="0,0" Duration="250"/>`, optionally under `<Animation Condition="…">`. `Type="Embedded"` binds a Java class: `com.group_finity.mascot.action.Look`, `…Dragged`, `…Breed` (`BornX`/`BornY`/`BornBehavior`), `…Fall`, `…Jump`, `…Regist`, `…WalkWithIE`/`ThrowIE`. Parameters become XML attributes (`Gravity="2"`, `RegistanceX="0.05"`, `VelocityParam="20"`, `IeOffsetX="6"`). `Duration` is in **ticks**, not ms |
| **Behavior DSL** | `behaviors.xml` → `<BehaviorList>` of `<Behavior Name= Frequency= Hidden=>` containing `<NextBehaviorList Add="true|false">` with `<BehaviorReference Name= Frequency= Condition=>`, grouped under `<Condition Condition="#{…}">`. Conditions are **Spring-EL-style expressions** over a live object graph: `#{mascot.environment.floor.isOn(mascot.anchor)}`, `${mascot.environment.workArea.left}`, `mascot.environment.activeIE.*`, `mascot.environment.cursor.dx/dy`, `mascot.environment.wall`/`.ceiling`, `mascot.totalCount`, `mascot.lookRight`, plus `Math.random()`. Actions accept `TargetX`/`TargetY` and initial velocities |
| **Mandatory elements** | **Four actions and four behaviors are mandatory or the file is invalid: `ChaseMouse`, `Fall`, `Dragged`, `Thrown`.** `PullUp` and `Divided` are also referenced by the defaults. Self-cloning is `Breed` + `SplitIntoTwo`, gated at `mascot.totalCount < 50`. This gives an adapter a well-defined minimum viable interpreter |
| **Notable semantics** | Shimeji treats the **desktop as a physics playground**: it walks the work-area floor, climbs walls, hangs from the ceiling, and interacts with *other applications' windows* (`activeIE` — the active Internet Explorer window, whose `topBorder`/`bottomBorder`/`left`/`right` become surfaces to stand on and throw things from). It also **breeds**, spawning new mascots from one image set |
| **Adapter difficulty** | **Trivial-to-moderate.** Everything is plain files: XML + per-frame PNG + a small expression evaluator, all permissively licensed. No binary parsing, no physics engine to port (gravity/bounce is a few lines), and the four mandatory actions bound the minimum viable implementation. The real work is faithfully implementing the `Sequence`/`Select`/`Embedded` composition semantics and the window-topology environment model |
| **Popularity** | The dominant historical desktop-pet ecosystem. Content is distributed on DeviantArt under the `shimeji` tag — [tag page](https://www.deviantart.com/tag/shimeji) — as free ZIP downloads by individual artists; `shimejis.xyz` maintains a browser-extension pack library. Kilkakon's "How to Download and Use" video: **1,342,518 views** ([YouTube](https://www.youtube.com/watch?v=S7fPCGh5xxo)). Fork star counts are small (52–165) but the format's user base is far larger than its GitHub footprint. Total asset count **unverified** |
| **Re-hosting** | **Yes** — New BSD/zlib code, and the community norm is packs distributed with the artist's consent. Individual character artwork remains each artist's copyright; the ecosystem has no per-pack license convention, so bundling is decided per pack |
| **Proof it ports** | Two independent reimplementations load Shimeji image sets without Java: [Shijima-Qt](https://github.com/pixelomer/Shijima-Qt) (C++/Qt6, **GPL-3.0**, 200★, now archived; `libshijima` engine + `libshimejifinder` pack parser) and [NeurolingsCE-Qt](https://github.com/qingchenyouforcc/NeurolingsCE-Qt) (C++17/Qt6, **GPL-3.0 + additional terms**, 45★, converts Shimeji ZIPs into a `.mascot` container, HTTP API on `127.0.0.1:32456`). Steam's *Desktop Pet Project* (app 2618940, $2.99) also ships a "Shimeji Import Manager" |

### 1.2 Ukagaka / 伺か / SSP (Ghost + Shell + Balloon)

| Field | Detail |
|---|---|
| **Canonical baseware** | **SSP (Sakura Script Player)** — <http://ssp.shillest.net/>. Windows 2000+ or Wine. **Freeware, not open source**; copyright C.Ponapalt + DOIchan!; no public source repository |
| **Spec** | **UKADOC** — [English translation](https://ukagakadreamteam.github.io/ukadoc/manual/index.html) / [Japanese original](http://ssp.shillest.net/ukadoc/manual/index.html). Self-describes as SSP's official documentation; also covers MATERIA period 583 and CROW 0.5.2 |
| **Note** | `github.com/ukagakadreamteam/ssp` **does not exist** — that org hosts only the English UKADOC translation. `github.com/Jasig/SSP-Platform` is an unrelated project (search false positive) |
| **Runtime** | Win32 native. SHIORI engines are **Windows DLLs** |
| **Content model** | A ghost = 1 master ghost + 1 master shell (a shell belongs to exactly one ghost). **Balloons are baseware-level**, shared across all ghosts |
| **Layout** | `<ghost>/ghost/master/` (`descript.txt` mandatory, `shiori.dll`, `*.dic`, `makoto.dll`, icons, `thumbnail.png`); `<ghost>/shell/master/` (`descript.txt`, `surfaces.txt`, `surface*.png`, `surface*.pna`, `element*.png`); `<ghost>/shell/<addshell>/`; top level `install.txt`, `readme.txt`/`.md`, `terms.txt`, `updates2.dau`, `delete.txt`, `developer_options.txt`. Balloons: `balloon/<name>/` with `descript.txt`, `balloons*`, `balloonk*`, `balloons*s.txt`, `balloonc*` |
| **Manifest format** | `descript.txt` — one `key,value` grammar at **three levels** (ghost / shell / balloon). Charset declared *inside* the file (`charset,Shift_JIS`). Priority chain: SHIORI Resource > shell descript.txt > ghost descript.txt. Two traps: values starting with `\` or `%` are discarded as SakuraScript/env tags (escape `\\`, `\%`) |
| **Shell animation** | `surfaces.txt` implements **SERIKO**. `surface*.png` where **pixel (0,0) is the transparency colour**; `surface*.pna` is a greyscale PNG renamed `.pna` supplying per-pixel alpha. **surface0 and surface10 are mandatory.** Elements composite a base surface (`element0,overlay,face.png,0,0,--clipping,10,10,50,50,--alpha,128`). Animations: `animation<ID>.interval,<keyword>` (keywords `bind, always, random1/2, random1/4, random<N>, periodic<N>, loop, once, never, starttalk, endtalk, talk<N>`) followed by `animation<ID>.pattern<N>,<surfaceID>,<wait_ms>,<drawing_method>,<x>,<y>` where **surfaceID `-1` stops that animation and `-2` stops all running animations**. ~35 drawing/blend methods (`base, overlay, overlay-fast, replace, reduce, asis, move, scaling, add, add-overlay, add-replace, add-reduce, insert, start, stop, alternativestart/stop, parallelstart/stop, import`, plus `blend-multiply|screen|overlay|add|softlight|hardlight|colordodge|color|luminosity|hue|saturation|…` each with a `-fast` twin that is *historical, not actually faster*). **`scaling` is the only method accepting fractional coordinates** |
| **Hitboxes** | `collision<ID>,<collisionID>,<left>,<top>,<right>,<bottom>,<name>` (rect) and `collisionex<ID>,…` (non-rectangular). Conventional names `bust`, `head`, `face`. Per-surface cursor overrides: `mouseup`/`mousedown`/`mouserightdown`/`mousewheel`/`mousehover` |
| **Balloon format** | **Not a uniform 9-slice.** `validrect.left/top/right/bottom` defines the inner drawable region (nothing drawn outside), `wordwrappoint.x` sets the wrap column, `origin.x/y` the tail anchor. Images `balloons*.png` (**even ID = left-facing, odd ID = right-facing**), `balloonk*` (side character), `balloonp2def*` (third character), `balloonc0..3` (input box), `arrow0/1`, `online0..15` (500 ms/frame), `sstp`, `marker*`, `clickwait*` |
| **Behavior engine** | **SHIORI** — a Win32 DLL with `__cdecl` exports `load`/`loadu`/`request`/`unload` using Windows Global Memory (HGLOBAL). Requests/responses are **HTTP-like header blocks** (CR+LF, terminated by a blank line) with headers `Charset, Sender, SenderType, SecurityLevel, Status, ID, BaseID, Reference0…N` and response `Value` = the SakuraScript to execute. Event taxonomy runs to several hundred IDs (`OnBoot`, `OnFirstBoot`, `OnClose`, `OnSecondChange`, `OnMinuteChange`, `OnMouseClick/DoubleClick/Move/Wheel/Hover/DragStart/DragEnd`, `OnCommunicate`, `OnTranslate`, …) |
| **Dictionary DSL** | **Deliberately not standardised** — "辞書ファイルの書式やフォーマットは決められているものではなく、SHIORI毎に異なる". Four incompatible engines: 華和梨 **Kawari** (`kawari.dll`), 文 **AYA** (`aya5.dll`), **YAYA** (`yaya.dll`, AYA's successor), 里々 **Satori** (`satori.dll`, the only 2-byte-grammar engine, open-sourced and maintained by SSP's own developer). Selected by `shiori,<dll>` in the ghost `descript.txt`. Satori concretely: `satori_bootconf.txt` for encoding, `characters.ini`, `satori_conf.txt`, dictionaries `dic*.txt` (`.sat` = encrypted), units delimited by lines starting `＊` (talk) or `＠` (word group), with tab-separated conditions and `（Ｒ０）`-style reference reads |
| **Scripting** | **SakuraScript** — a full imperative language: scopes `\0`/`\1`/`\p[N]`, surfaces `\s[ID]`, animations `\i[ID]`, dressup `\![bind,…]`, `\![set,scaling|alpha|zorder|sticky-window,…]`, `\![move,…]`/`\![moveasync,…]`, `\![enter|leave,passivemode|inductionmode|selectmode|collisionmode]`, `\![reload,shiori|shell|balloon|ghost]`, and `\![execute,…]` which can issue HTTP verbs, extract/compress archives, install nars, `ping`, `nslookup` — several of which SSP sandboxes to its own folders and a new host **must** sandbox too |
| **Distribution** | **`.nar` is a ZIP renamed to `.nar`** ("Nanika ARchive"), triggered by a top-level `install.txt` (`charset`, `name`, `type`, `directory`, `accept`, `refresh`, `refreshundeletemask`). Types: `ghost, shell, supplement, package, balloon, plugin, headline, calendar.skin, calendar.plugin` |
| **Network updates** | `homeurl,http://host/path/` in `descript.txt` points at the update folder. **`updates2.dau` (v2)** and **`updates.txt` (v3)** are **byte-value-1-delimited**, CRLF-terminated, with an MD5 per file and optional `size=`/`date=` fields, and the charset smuggled into the *last field of the first entry*. Upload **must be binary mode**. Updates **overwrite, never synchronise** — hence `delete.txt` (SSP only). A `file,`/`charset,` prefix distinguishes v3 |
| **Adapter difficulty** | **Hard, with a legally-blocked sub-component.** Legally blocked: porting SSP itself (no source, freeware, Windows binaries) — a new host can only be a **clean-room reimplementation of the documented spec**. Technically hard because (1) SHIORI is a Win32 DLL you must either emulate or run under Wine; (2) you cannot bypass SHIORI since dictionary formats are per-engine; (3) SERIKO is a small 2D compositor with ~35 blend modes; (4) SakuraScript is an imperative interpreter with sandboxable side effects; (5) the transparency model is a colour key + separate `.pna` alpha, not plain PNG alpha; (6) two update-file generations |
| **Cheapest viable path** | Not a from-scratch host: a spec-faithful reimplementation targeting **one** SHIORI engine first — **Satori** is the pragmatic choice (complete public documentation, open-sourced, maintained by SSP's own author) — with a real PNG compositor and the transparency-key + `.pna` model. Everything else can answer a 204 no-response and be added incrementally, because the protocol is simple line-oriented text and a baseware is allowed to say nothing |
| **Popularity** | The dominant Japanese ecosystem since 2000-05-25. Galleries: [GHOST TOWN](http://ghosttown.mikage.jp/), [Encyclopedia of 伺か](http://dic.sstp.jp/), [伺かwiki](http://www.towano.net/ua-ks/). English community: [Ukagaka Dream Team](https://github.com/ukagakadreamteam) (Tumblr + Discord). Total ghost count and SSP download counts **unverified** — no gallery publishes totals |
| **Re-hosting** | **No blanket permission.** Ghost authors' terms vary per ghost, carried in `readme.txt` / `terms.txt` (the latter triggers a license dialog before `.nar` install — UKADOC says to omit it unless genuinely necessary). The community actively polices this: [r/ukagakaghost "Please stop redistributing Ukagaka"](https://www.reddit.com/r/ukagakaghost/comments/1nuiocz/please_stop_redistributing_ukagaka/) — "Most ghosts include redistribution terms in their README, license files, or on their original websites… Even when permissions aren't explicitly denied, those rights are still reserved." A host must therefore treat ghost packs as **user-supplied, never bundled** |

### 1.10 Live2D Cubism — the legal chokepoint

This deserves its own section because it gates the single largest 2D character ecosystem (Bongo Cat, VTube Studio, Live2DViewerEX, and most VTuber content), and because **the blocker is a licence clause, not an SDK technicality.**

| Field | Detail |
|---|---|
| **Canonical** | <https://www.live2d.com/en/sdk/license/> · EULA: [Live2D Proprietary Software License Agreement](https://www.live2d.com/eula/live2d-proprietary-software-license-agreement_en.html) (v2.1, revised 2025-02-03) |
| **Two licences, two components** | **Cubism Core** (`live2dcubismcore.js`/`.min.js`/`.d.ts`, native `Live2DCubismCore.dll`/`.so`/`.a`) is under the **Proprietary** licence; the surrounding SDK framework is under the **Open Software** licence. ## 2. Ranked support order (impact vs adapter cost)

Ranking is by (content volume reachable) ÷ (engineering + legal cost), with a bias toward ecosystems whose **assets** can be read without shipping someone else's runtime.

| # | Ecosystem | Why this position | Cost |
|---|---|---|---|
| **1** | **Codex Pets / OpenPets `pet.json` + sprite atlas** | Trivial to implement; **MIT**; a fixed 8×9/57-frame geometry with a 9-name animation vocabulary that maps 1:1 onto any host's state machine; **1,307 ready-made companions** already in the OpenPets gallery; and it is the only format with a first-party (OpenAI Codex) backer. This should be the **host's native format**, not an adapter | **Trivial** |
| **2** | **Shimeji / Shimeji-ee** | The largest historical content library, all of it plain readable files, under **New BSD / zlib**. Two independent non-Java reimplementations (Shijima-Qt, NeurolingsCE) already prove the format ports, so the risk is known. Four mandatory actions (`ChaseMouse`, `Fall`, `Dragged`, `Thrown`) bound a minimum viable interpreter. The adapter removes the Java dependency, which is the ecosystem's single biggest pain point | **Trivial-to-moderate** |
| **3** | **Aseprite / GIF / APNG / spritesheet atlas** | Near-zero cost, no runtime license, and it is what artists actually author in. Extends the native pipeline rather than adding a new one | **Trivial** |
| **4** | **Ukagaka / SSP** | The highest **moat** in the survey: a 25-year Japanese content library with a real scripting language, real physics-free compositing, and no viable modern host. It is also the hardest, so it should be attacked *after* the renderer core is proven. Stage it: SERIKO shell renderer → one SHIORI (Satori) → a Win32 SHIORI compat layer | **Hard** |
| **5** | **VRM / VRMA** | The **best-specified 3D option** and the only format with **machine-readable license flags a host can enforce in the UI** — that turns the licensing minefield into a product feature. MIT runtimes (three-vrm, godot-vrm). Desktop Mate's 1.5M downloads and 23k concurrent peak prove demand | **Moderate** |
| **6** | **Live2D Cubism — metadata layer only** | **Demote from "adapter" to "cataloguer".** The ecosystem is huge (Bongo Cat 23.9k★, Live2DViewerEX ~3.4k reviews, VTube Studio, most VTuber content), but shipping arbitrary user `.moc3` rendering is **not legally available**: the Cubism EULA §1.5 "Expandable Application" clause describes a pet host exactly, and §2.2 excludes it from the small-enterprise exemption. **Do the JSON layer now** (`.model3.json`/`.physics3.json`/`.motion3.json`/`.exp3.json`/`.cdi3.json` are open and documented — enough to catalog, validate, preview metadata and convert), and treat rendering as a business decision requiring Live2D's pre-approval | **Trivial** (metadata) / **legally blocked** (rendering) |
| **7** | **VPet** | Apache-2.0 code and a real Steam audience, but it is a **runtime**, not an asset format — supporting it means hosting a WPF/C# plugin ABI. Highest cost-to-value of the live options | **Hard** |
| **8** | **MMD** | Rich free content, but a hard binary format and a licensing minefield. Worth supporting as a **user-supplied local file** reader only; never bundle | **Hard** |
| **9** | **RunCat runners** | Small, cute, active (RunCat365 10.3k★), and the format is undocumented so it is cheap to reverse. Low impact | **Moderate** |
| **10** | **Spine** | Only after purchasing a Spine Editor license, and even then the license propagates to downstream users. Last | **Blocked without purchase** |

**Rationale for the shape of this order.** Every ecosystem that has *ever* been successfully re-hosted (Shimeji, oneko, Codex Pets) is one where the assets are **files a host can read**. Every ecosystem that has *never* been re-hosted (Live2D, Spine, Ukagaka's SHIORI, Flash, Wallpaper Engine Workshop) is one where the assets are **gated behind a licensed SDK, a Windows DLL, or DRM**. The ranking therefore tracks "can we read the bytes?" first and "how many bytes are there?" second.

## 3. Common-denominator analysis

What a unified internal pet model must express to cover the top ecosystems. Each row names the ecosystems that force the capability.

| # | Model capability | Required by | Notes |
|---|---|---|---|
| 1 | **Identity & provenance** — id, display name, author, source format, source URL, thumbnail | all | Also carries the **declared redistribution permission**, which must be a first-class field, not a comment |
| 2 | **Machine-readable license/permission block** — allowed audience, commercial use, modification, redistribution, credit required | VRM (both vocabularies), VPet animation terms, per-pack prose elsewhere | The only ecosystem that supplies this today is VRM. For everyone else the host must let a pack *declare* it and default to "not redistributable" |
| 3 | **Logical canvas + anchor** — surface size, anchor point, per-frame origin offset | Shimeji (`ImageAnchor="64,128"`), Ukagaka (`baseposition.x/y`, default centre-x/bottom), Codex Pets (192×208 cell) | Needed for correct feet-on-floor placement and for switching between differently-sized surfaces without drift |
| 4 | **Frame sprite** — ordered still images, per-frame duration, per-frame offset, per-frame velocity | Shimeji (46 PNGs/character), Ukagaka (SERIKO `pattern`), Codex Pets atlas, GIF/APNG, Aseprite tags | The universal baseline. Note Shimeji durations are ticks and Ukagaka's are milliseconds, with `min-max` random ranges |
| 5 | **Composite sprite** — base layer + ordered elements with blend mode, clipping rect, per-element alpha | Ukagaka SERIKO only (~35 blend modes, `--clipping`, `--alpha`, `insert` for nested z-order) | Nothing else needs it, but skipping it visibly breaks dressup ghosts |
| 6 | **Colour-key + separate alpha channel** | Ukagaka (pixel (0,0) is the transparency key; `.pna` greyscale alpha; `seriko.use_self_alpha` opt-in) | A renderer that assumes straight PNG alpha renders Ukagaka shells wrongly |
| 7 | **Skeletal 2D** — bones, slots/skins, deformable meshes, timelines, draw order | Live2D, Spine, DragonBones | Live2D adds physics-driven parameters (`physics3.json`) |
| 8 | **Model 3D** — glTF scene graph, humanoid rig, morph/expression targets, node constraints | VRM, VRMA, MMD | MMD needs Bullet rigid bodies + joints; VRM needs Verlet spring bones with sphere **and** capsule colliders |
| 9 | **Hosted/opaque surface** — an embedded renderer the host cannot introspect (webview, Flash, native window) | Wallpaper Engine web, Flash `.swf` | Essential as an escape hatch: it lets a host ship *something* for an ecosystem whose internals it cannot parse, while the licence question is unresolved |
| 10 | **Named animation clips** — id, loop mode, duration, blend, exclusivity, parallel/alternative start-stop, and per-clip hitboxes | Ukagaka (`interval` keywords `bind/always/random1/2/periodic<N>/loop/once/never/starttalk/endtalk/talk<N>`, `option,exclusive`, `option,background`), Aseprite tags, Codex Pets rows | Ukagaka's exclusivity model is the richest: an exclusive animation stops all others, and SSP can scope it to specific IDs |
| 11 | **Hitboxes / collision regions** — named, per-surface, rect and non-rect, with per-region cursor and tooltip | Ukagaka (`collision`, `collisionex`, `mouseup/mousedown/mouserightdown/mousewheel/mousehover`), Shimeji (implicit whole-sprite drag) | Named regions are how ghosts implement "pat the head" |
| 12 | **Behaviour graph** — nodes = actions/clips, edges = guarded transitions with probability/priority/cooldown | Shimeji `behaviors.xml`, Ukagaka animation intervals | Covers the majority of pet behaviour declaratively |
| 13 | **Scripted behaviour escape hatch** — a sandboxed host-language VM | Ukagaka SHIORI (four engines, DLL-hosted), Shimeji `${…}` JS expressions, SakuraScript's imperative commands | The single most important architectural decision. Without it, adapters that cannot express their source semantics declaratively are impossible; with it, `\![execute,…]`-style side effects must be capability-gated |
| 14 | **Physics & motion** — gravity, drag, bounce, walk/run/dash velocity, throw with initial velocity, jump | Shimeji (`Gravity`, `RegistanceX/Y`, `InitialVX/VY`, `VelocityParam`), VRM spring bones, Live2D `physics3`, MMD Bullet | Also: **screen-edge/floor/wall/ceiling constraint types** (`BorderType`) and **window-topology awareness** — Shimeji walks on and throws things from other applications' windows |
| 15 | **Multi-display & topology** | all modern hosts | OpenPets documents the concrete traps: per-monitor position memory, clamping after monitor changes, cross-display roaming, and **Wayland forbidding clients from positioning their own toplevels** (so it forces the X11/Ozone backend) |
| 16 | **Balloon / speech** — text pools, localization, frame model, tail anchoring, rich text, choices, input boxes, click-wait | Ukagaka (the richest: `validrect` + `wordwrappoint` + `origin` + 4-direction frames + `balloonc*` input boxes), Codex Pets (reaction → speech pool), OpenPets (localized pools) | Ukagaka's balloon is explicitly **not** a uniform 9-slice |
| 17 | **Input & interaction** — drag, throw, click, double-click, right-click, wheel, hover, context menu, click-through with forwarding | Shimeji, Ukagaka, OpenPets | Click-through has real platform traps: Electron forwards mouse events on macOS/Windows but **not Linux**, and forwarding can silently die (macOS Space switches, Windows rapid reloads) — OpenPets runs a cursor-probe watchdog to re-arm it |
| 18 | **Time & external events** — boot/close, per-second/minute tick, OS status (battery, CPU, display, session lock), and *agent/application* state | Ukagaka (`OnSecondChange`, OS status, battery, headline/RSS, SSTP), RunCat (CPU), OpenPets/UniPet (coding-agent state) | The agent-state channel is what makes a modern pet *useful* rather than merely decorative |
| 19 | **Audio** — BGM and per-action sound effects | VPet, Ukagaka, NeurolingsCE (optional Qt Multimedia) | — |
| 20 | **Persistence** — save state, last position, learned/unlocked content | Ukagaka, VPet, RunCat | Position memory is per-monitor |
| 21 | **Content packaging & integrity** — a container, a manifest, and a safe extraction path | Ukagaka `.nar` (ZIP), Codex Pets (ZIP as transport), OpenPets (hash-pinned ZIP, path-traversal/symlink/case-collision checks, size caps) | OpenPets' ZIP safety rules are the reference implementation to copy: HTTPS-only allowlisted hosts, no encrypted entries, stored/deflate only, required files, atomic extraction |
| 22 | **Update mechanism** | Ukagaka (`homeurl` + `updates2.dau`/`updates.txt`, MD5 per file, overwrite-not-sync, `delete.txt`), OpenPets (hash-pinned catalog) | Ukagaka's is the only *standardised* one; a modern host should use signed manifests instead |

**Minimum viable core.** Rows **1, 3, 4, 10, 12, 13, 14, 16, 17, 18, 21** cover Codex Pets, Shimeji, Aseprite/GIF and a first-pass Ukagaka shell renderer. Rows **5, 6, 11** unlock full Ukagaka. Rows **7, 8** are the skeletal/3D tier. Row **9** is the escape hatch that lets the host ship *something* for Flash and Wallpaper Engine without parsing them.

### Why every previous attempt stopped where it did

1. **Skeletal and 3D formats each drag in a licensed SDK.** Live2D's Cubism Core is under a proprietary license, and its **"Expandable Application" clause (§1.5) describes a universal pet host by name** — unbounded user-supplied models — while **§2.2 excludes exactly that case from the small-enterprise exemption** that makes every other Live2D project free. Spine requires a paid editor license at integration time and propagates that requirement to downstream users. A universal host must either buy in or leave the tier out.
2. **The richest ecosystem's scripting layer is a Windows DLL.** Ukagaka's SHIORI cannot be reimplemented incrementally, because you cannot run *any* real ghost until you support at least one full dictionary engine — and there are four.
3. **Content licenses are per-pack prose.** No aggregator can legally ship a bundle, so a universal host can never ship a compelling *content* library the way a console emulator ships ROMs. It can only ship a *reader*. This is why OpenPets invested in its own gallery of MIT-licensed pets instead — and why its format narrowed to a sprite atlas.
4. **Transparency and click-through are the unglamorous hard part.** Every host must solve transparent, frameless, always-on-top, click-through, positionable windows — and the platform APIs differ (Wayland forbids client positioning; Electron mouse-forwarding silently dies; Tauri lacks WebGL2 on some platforms). This is where a lot of attempts quietly die.

### The recurring tell: encrypted containers

`.lpk` (Live2DViewerEX), `scene.pkg` (Wallpaper Engine), Desktop Mate's DLC packs, and `.moc3` itself are all **opaque by design**, and in every case a third-party unpacker exists precisely *because* the vendor documented nothing (`LpkUnpacker`, `rePKG`, and for `.moc3` the reverse-engineering that §6.4 forbids). Encrypted containers are therefore a reliable signal of an ecosystem that is **hostile to third-party hosts**, and they are where licence risk concentrates. Conversely, every ecosystem that has *ever* been successfully re-hosted — Shimeji, oneko, Codex Pets — ships plain files. **That correlation, not popularity, should drive the support order.**

**The gap this project would fill.** No surveyed project combines (a) a per-format **adapter** architecture, (b) **sprite + skeletal + 3D** in one renderer, (c) **scripted behaviour** with a sandbox, and (d) **enforced content licensing**. OpenPets owns (a) partially and (d) not at all; Shijima-Qt owns one format; Ikagaka.js tried the hardest format and stalled. The compatibility moat is real and unoccupied — but the evidence says it must be built **cheapest-format-first**, with the licensing model as a first-class feature rather than an afterthought.
